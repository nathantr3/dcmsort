Plan to fully implement an electron based (with HTML, CSS, and JavaScript) UI program that can be run in either Mac or Windows (we will use mac for testing since we are on a Mac) that allows interactive sorting, splitting, and attribute modification for dicoms. The idea is that the use would select a directory and it would be recursively searched for dicoms. All found dicoms would be parsed to understand their relation to each other and then presented in a nested list (exam, series, dicoms). Exams can be expanded and show the series. Series are then selectable (one or more) to pass to the core functionality of the program. All dicoms from the selected series are listed (just their file names under a collapsable list of series, kinda like an explore side bar in vs code) on the far left. Then the core idea of the program is to allow the user to define rules to split/join dicoms into separate series and modify things like series numbers, series descriptions (and.or just modifying prefixes and suffixes).

The inspiration for this project comes in large part from the dcmsplit tool (/Users/nate/Documents/code/dcmsplit) that wasn't general enough to cover modifying groups of dicoms that aren't simplying mulit-frame. For example, I have a set of dicoms that are multi-slice, multi-phase (x,y,z,t) stacked together with both a set of multi-slice single phase (x,y,z -- same locations, different frame/recon method) and multi-slice, multi-phase images (x,y,z,t - another unique frame). Since "phase index" isn't always a reliable a dicom attribute, it should detect that data as (x,y,z,p) where "p" is the phase index. If data doesn't fit in a single (x,y,z,p) matrix (because maybe the x/y/z locations are different in the different phases) then it would call those volumes. A single series may have multiple volumes.

The first thing it needs to do is analyze the dicoms and tell the user the different type of data present. For example, volume 1: 58 slices, 9 phases, volume 2: 58 slices, 3 phases). Then allow the user to define sorting rules by adding one or more child series (e.g., child series 1: FROM volume 1 SELECT slices * AND phases 1-3) Bascially, use sqlite to write the rules, but make it a GUI experience, not a raw text experience. Then, once a series rule is defined, you can modify it's attributes (i.e., Series Number scale and offset, see the dcmsplit tool, and series description new, prefix, suffix, etc). When a series rule is defined, the listed dicoms should highlight to a unique color that matches a color icon/label for that child series.

Then you should be able to click export which allows you to either write in-place OR save to a new folder.

The Set of Series Rules should be able to be saved/loaded.
